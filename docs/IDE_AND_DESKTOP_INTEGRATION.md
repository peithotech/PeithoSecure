# LLM Desktop App & IDE Integration Guide

Peitho seamlessly protects **Claude Desktop, Cursor IDE, Windsurf, Antigravity, and VS Code (Continue.dev)** from prompt injection attacks, unauthorized file access, and destructive commands.

---

## 1. Claude Desktop Integration

Claude Desktop launches MCP tool servers over standard OS pipes (`stdio`). You can shield any MCP tool server (filesystem, Postgres, GitHub, bash) by prefixing it with `peitho wrap`.

### Configuration Path:
* **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`
* **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`

### Example `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "secure-filesystem": {
      "command": "peitho",
      "args": [
        "wrap",
        "--target", "npx -y @modelcontextprotocol/server-filesystem /Users/me/Projects",
        "--token-file", "/Users/me/.peitho/tokens/claude_readonly.bin"
      ]
    },
    "secure-postgres": {
      "command": "peitho",
      "args": [
        "wrap",
        "--target", "npx -y @modelcontextprotocol/server-postgres postgresql://localhost/mydb",
        "--token-file", "/Users/me/.peitho/tokens/claude_staging.bin"
      ]
    }
  }
}
```

### How Claude is Protected:
1. When Claude legitimately reads files inside `/Users/me/Projects` $\rightarrow$ **Allowed**.
2. If an untrusted webpage or user prompt tricks Claude into calling `rm -rf /` or reading `/etc/passwd` $\rightarrow$ **Peitho intercepts and rejects the command before it ever executes**.

## 2. Cursor IDE & Windsurf Integration

Cursor and Windsurf support connecting to Model Context Protocol (MCP) servers via Streamable HTTP/SSE.

### Steps:
1. Start your local Peitho Security Gateway:
   ```bash
   peitho dev --port 4040
   ```
2. Open **Cursor Settings** $\rightarrow$ **Features** $\rightarrow$ **MCP Servers** $\rightarrow$ **Add New MCP Server**.
3. Fill in the connection details:
   * **Name**: `Peitho Security Gateway`
   * **Type**: `Streamable HTTP / SSE`
   * **URL**: `http://127.0.0.1:4040/mcp`
4. Now, all tool requests generated by Cursor's AI agent pass through Peitho, and live traces appear at `http://127.0.0.1:4040`.

## 3. Antigravity & Custom LLM Agent Frameworks

If you are using Google Antigravity, LangChain, CrewAI, or Microsoft AutoGen:

### Mode A: Python / TypeScript `@shield` Decorator
Wrap your custom agent tools directly in code:
```python
from peitho import shield

@shield(token=agent_token)
def execute_sql(query: str):
    return db.execute(query)
```

### Mode B: Direct HTTP JSON-RPC Client
Send standard JSON-RPC 2.0 tool calls with capability authorization headers:
```python
import urllib.request
import json

req = urllib.request.Request(
    "http://127.0.0.1:4040/mcp",
    data=json.dumps({
        "jsonrpc": "2.0",
        "id": 1,
        "method": "tools/call",
        "params": {
            "name": "search_docs",
            "arguments": {"query": "Q3 report"},
            "principal": "agent.researcher"
        }
    }).encode("utf-8"),
    headers={
        "Content-Type": "application/json",
        "Authorization": f"Bearer {token_hex}"
    },
    method="POST"
)
resp = urllib.request.urlopen(req)
```

## 4. Verifying Interceptions Live in the UI

Whenever your IDE or desktop app calls a tool:
1. Open **[http://127.0.0.1:4040](http://127.0.0.1:4040)**.
2. View the **Activity Stream** table to see the incoming principal and latency.
3. If an action violates token scope, click on the row in the dashboard to inspect the blocked invariant rule.
